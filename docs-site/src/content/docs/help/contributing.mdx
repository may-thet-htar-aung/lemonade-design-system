---
title: Contributing
description: How work lands in the repository.
---

- **Never push or merge to `main`.** Work lands by pull request into `staging`; a human merges `staging` into `main`.
- Branches: `component/<name>`, `docs/<name>`, `release-review/<name>` and `tokens/sync-<description>`. Branch from an up-to-date `staging`.
- **Never hand-edit `tokens/` or `build/`.** Both are generated. Fix a token in Figma and export it again, then run `npm run build:tokens` and `node scripts/verify-tokens.mjs`, which must end `RESULT: PASS`.
- Each component lives in `src/components/<Name>/` as `<Name>.tsx`, `<Name>.css` and `<Name>.stories.tsx`. The story file starts with its Figma node URL, and there is one story per Figma variant.
- Every CSS value is a semantic token. Components do not import CSS. A Cleared component's CSS (and the CSS of anything it renders) is imported in `src/styles.css`; every other component's is in `src/styles.unreleased.css`. When a component clears, move its line across and add it to `src/index.ts`.
- `npm run typecheck` must exit 0.

The full process, and the agent crew that runs it, is in `CLAUDE.md` and `docs/lime-crew-spec.md`.
