# Astro page

The docs site is regenerated whole on every run, never one page at a time. A page built alone sits next to pages built from an older commit, and the site then says two different things about the same system.

Use this for every Doc-generator Job B run: staging the site beside a release, and taking it live after the publish. Do not use it to write intent files (that is `component-intent`) or to change a component.

The format to match is **https://horizon-docs-alpha.vercel.app**. Open it before your first run and match its structure: splash home, sidebar groups, a component page's header strip and tabs.

## The rule about sources

**A missing source shows a notice. It never gets invented content.** When a section has nothing to draw from (no intent file, no Figma usage region, no story, no tag), keep the section where it belongs and put a Starlight `<Aside type="caution">` in it naming exactly what is missing and where it was looked for. Roadmap and News state no date, owner or priority that a source does not state.

## Where it lives

| What | Where |
|---|---|
| The site | `docs-site/`, its own npm package (Astro + Starlight), on the `astro` branch |
| Deploys | A Vercel project with root directory `docs-site` and production branch `astro`. Every push to `astro` deploys it. `docs/tools.md` records the folder, the project and the production URL |
| Other branches | Carry only `docs-site/vercel.json` = `{"git": {"deploymentEnabled": false}}`, so they never build the docs project |

Never deploy by hand. Push to `astro`, and Vercel deploys.

## The sidebar

Written out in `docs-site/astro.config.mjs`, in this order, every entry an explicit `slug`, so a missing page **fails the build** instead of vanishing from the navigation. Never use `autogenerate`.

| Group | Pages, in order |
|---|---|
| Get Started | Changelog, Roadmap, News, Versioning, Upgrading |
| Designing | Introduction |
| Developing | Introduction, React, React Router |
| Skills | Knowledge skill |
| Core | Components (All components, then one page per component, in registry order), Tokens |
| Styling | Theming |
| Help | FAQ, Report a bug, Request a feature, Contributing, Embedding |

The per-component entries are written by the generator into `docs-site/src/generated/components-sidebar.json` as explicit slugs, which `astro.config.mjs` imports. Each one is still an explicit slug, so a missing page still fails the build.

## What is generated and what is written

**Generated, never edited by hand:** Home, All components, every component page, Tokens, Changelog, Roadmap, News. Each starts with a comment saying it is generated by `docs-site/scripts/generate.mjs`. To change one, change the generator or its sources and run it again.

**Written from the repo:** every guide (Versioning, Upgrading, Designing and Developing pages, Knowledge skill, Theming, every Help page). Each run, re-read each guide against the code at the pinned commit and correct any sentence that has stopped being true: a command, a prop name, an import path, a file location. Do not add new claims while doing it.

## The generator

One script, `docs-site/scripts/generate.mjs`, run as `node scripts/generate.mjs --commit <sha>`. It reads:

| Input | What it is | Who makes it |
|---|---|---|
| The repo at the pinned commit | Components, intent files, stories, `src/index.ts`, `README.md`, `build/css/tokens.css`, `git log`, tags. Read with `git show <sha>:<path>`, never from the working tree | — |
| `docs-site/src/data/board.json` | The registry's statuses per component: name, Development, Release Verdict, Figma URL, Production Storybook URL. **No record IDs** | You, each run, from a plain list of `Components` |
| `docs-site/src/data/figma.json` | The live Figma reads per component: node, variant matrix, bound and unbound values, documentation page text | You, each run, over the Figma connection |
| The deployed Storybook's `index.json` | Every story ID and title | Fetched by the generator from the production Storybook URL |

The generator copies `build/css/tokens.css` from the pinned commit into `docs-site/src/styles/tokens.css`, so the site wears the tokens of the commit it documents.

## Home

A Starlight splash page (`template: splash`).

1. **Hero line**: the README's first paragraph, verbatim.
2. **Buttons**: Start designing (→ Designing / Introduction), Start coding (→ Developing / Introduction), Open Storybook (→ production Storybook).
3. **Latest release**: the newest `v*` tag and its install command, `npm install <package name>@<version>` with the name from `package.json`. No tag yet: a notice saying nothing is published.
4. **Link cards** to Designing, Developing, Components and Tokens.

## A component page

`docs-site/src/content/docs/components/<slug>.mdx`, only for a component whose `board.json` row reads `Completed` or `Released` with `Release Verdict` = `Cleared`.

**Header strip**: status (Development, from `board.json`) and the version it shipped in (the earliest `v*` tag containing the commit that added the component; none yet: "unreleased"), then links to Storybook, the Figma node and the source folder on GitHub at the pinned commit.

**Five tabs, in this order**, using Starlight `<Tabs>`:

| Tab | Content | Source |
|---|---|---|
| **Usage** | When to use · where it goes · when not to, each with its alternative · best practice · what each variant is for · accessibility facts, each linked to its source line on GitHub · composition (what it renders, what renders it) · what this version promises | `<Name>.intent.json`, `src/index.ts`, the changelog |
| **Examples** | The README usage example, then every story that is **not** a variant-matrix row, embedded live from Storybook (`/iframe.html?id=<id>&viewMode=story`) in light and in dark | `README.md`, `index.json`, `figma.json` (to tell matrix rows apart) |
| **Code** | The import line · props with defaults and doc comments · union types · the tokens it needs, with light and dark values · Storybook's own props table embedded | The `.tsx`, `required_tokens`, `tokens.css`, the story's docs entry in `index.json` |
| **Design** | The Figma node embedded · the variant matrix, every row linked to its story · both themes · every value Figma never bound · the design gaps recorded against it | `figma.json`, `index.json`, the QA report and Staging Testing |
| **Changelog** | `git log` for the component and the components it renders, each commit marked with the version it shipped in (the earliest tag containing it, or "unreleased") | `git log`, tags |

- **Dark rendering**: use the deployed Storybook's mode switch if it has one. If it has none, embed light and put a notice in place of dark, naming the missing switch.
- **Props table**: embed the story's docs entry when `index.json` has one. When it has none, put a notice saying Storybook has no docs page for it.
- **Leave out of the Design tab** the two items the Designer has ruled out of scope: the Icon artwork fill (`#2A313A`, unbound; the icon inherits `currentColor`) and the absence of a designed focus ring (components keep the browser's default `:focus-visible` outline).

## Tokens, Changelog, Roadmap, News

- **Tokens**: every semantic token in `tokens.css`, grouped by family, with its light and dark value and the modes that change it. Base tokens are listed separately and marked as never used in components.
- **Changelog**: one section per `v*` tag, newest first, with added, changed, fixed, deprecated and removed, from the commits between tags. Untagged commits sit under "Unreleased".
- **Roadmap**: components on the board that are not yet `Completed`, with their Development status. No date, owner or priority unless a source states it.
- **News**: one entry per published version, from its tag and changelog. No date that the tag does not carry.

## The site's look

One stylesheet, `docs-site/src/styles/lemonade.css`, maps Starlight's `--sl-color-*` and `--sl-font*` variables onto Lemonade semantic tokens. It holds **no hex of its own**, and no base token. Starlight's dark theme is mirrored onto `data-semantic="dark"` so the dark token values apply. Fonts (Manrope, Noto Sans Myanmar) are self-hosted from the site's own files, never loaded from Google Fonts.

## Before pushing

- [ ] `generate.mjs` ran against the pinned commit, with this run's `board.json` and `figma.json`.
- [ ] Every guide was re-read against the code, and each sentence that stopped being true was corrected.
- [ ] `npm run build` in `docs-site/` succeeds, with **zero broken internal links**.
- [ ] You opened the home page, one component page (every tab) and Tokens, in light and in dark, and each rendered with content.
- [ ] No component page exists for a component that is not `Completed` or `Released` with `Cleared`.
- [ ] No generated page was edited by hand. `git diff` shows changes to generated pages only where the generator wrote them.
- [ ] `lemonade.css` has no hex.

## After deploying

Wait until the Vercel deployment for your commit reads success. Then:

- [ ] Fetch every live page (the built site's page list). Each returns 200.
- [ ] Each component page has all five tabs, and each tab has content or a missing-source notice.
- [ ] Every header link returns 200, except a Figma link to a team-only file, which may answer 403.

**Only then** write each verified component page's URL to `Components.Astro Link`, and read it back. A component whose page failed gets nothing written. If verification fails, write nothing for it and report it.

## Never

- **Never build one page alone.** The whole site, every run.
- **Never hand-edit a generated page.** Fix the generator or its sources.
- **Never invent content for a missing source.** Show the notice.
- **Never state a date, owner or priority** on Roadmap or News that a source does not state.
- **Never use `autogenerate`** in the sidebar, or let a missing page drop out silently.
- **Never put a hex value or a base token** in the site's stylesheet, or load fonts from a third party.
- **Never put a record ID** in `board.json` or anywhere in the site.
- **Never deploy by hand,** and never push while a release is running before the publish.
- **Never write an Astro Link you have not fetched.**
