# Build a component

One design node in, one component out. Four stages, in order. Each stage ends with a **check**. A check is green or it is red, and you do not start the next stage while it is red. Fix the stage and run the check again, or stop and report what blocks you. Carrying a red check forward is never an option.

Use this for one component set in Figma becoming one component in `src/components/<Name>/`, whether it is a new build or a repair after a QA finding. Do not use it for a screen, a page, or anything spanning more than one node.

This skill ends when the component is verified locally. Deploying to staging and writing the registry is the Engineer's **register** stage, in `.claude/agents/engineer.md`. It starts only after stage 4 is green.

## The rule about gaps

**A property the design leaves unbound is a design gap to report, not a decision to make.** If the node gives a fill, a stroke, a radius, a spacing value or a type style as a raw value with no variable bound, the design has not said which token it means. You do not pick the nearest token, copy the raw value, or "use what looks right". You list it as a gap, build everything else, and leave that one property for the Designer to bind. A guessed token looks finished and hides the question the Designer needed to answer.

## Stage 1 · Read the design: the variant matrix

Pull the node from `Components.Figma` over the Figma connection:

- `get_metadata` on the component set: every variant, with its real width and height.
- `get_design_context`: the layout, and the variable bound to each property.
- `get_screenshot`: what each variant looks like.

Write down the **variant matrix**: every variant property and its values, every size and every state. Multiply them out, one row per combination the component set actually contains. Note any combination that is missing from the set, because a missing combination is not one to invent.

For each row, also write down every visual property the design defines (fill, stroke, radius, padding, gap, type style, effect, opacity) and what it is bound to: a variable name, or **unbound**.

This matrix is the contract. It sets the props, it sets the stories, and it is exactly what QA will test against the same node.

**Check (must be green):**
- [ ] The number of matrix rows equals the number of variants `get_metadata` returns for the set.
- [ ] Every variant property in Figma appears as a column, and every value of it appears in at least one row.
- [ ] Every visual property on every row is recorded as bound (with its variable name) or unbound.
- [ ] Nothing is written as "TBD" or "work it out later".

## Stage 2 · Resolve every value to a semantic token

The tokens live in `build/css/tokens.css`. That file is generated by `npm run build:tokens`. Read it, never edit it.

That file has two layers:
- **Base tokens** are the raw scales that other tokens point at. `--color-forest-green-600` is a base token because `--color-bg-brandgreen-idle: var(--color-forest-green-600);` points at it.
- **Semantic tokens** carry a meaning: `--color-bg-brandgreen-idle`, `--gap-gutter`. Some scales have no alias layer, such as `--border-radius-md` and `--fontsize-md`. Those are the tokens to use, because nothing sits in front of them.

The test is mechanical: **if another token in the file points at a token through `var(--…)`, that token is base, and a component never uses it.** Use the token that points at it, the one whose name says what it is for. A base token in a component skips the layer that gives a value its meaning, and it breaks when a theme (`[data-semantic="dark"]`, `[data-layout]`, `[data-typography]`) remaps the semantic layer.

For each bound property, find the semantic token that matches the Figma variable, and write the mapping into your matrix. For each unbound property, write **gap**. Do not resolve it.

**Check (must be green):**
- [ ] Every bound property maps to a token that exists in `build/css/tokens.css`.
- [ ] No token you mapped is the target of another token's `var(--…)` in `build/css/tokens.css`.
- [ ] Every unbound property is listed as a gap, with the node, the variant and the property. None has been given a token.
- [ ] No token was invented. If a Figma variable has no token in the file, that is reported as a missing token, and you stop. Do not substitute another token.

## Stage 3 · Implement: structure and real behaviour

Create `src/components/<Name>/<Name>.tsx` and `<Name>.css`.

- **Props mirror the design.** Prop names match the Figma property names character for character, and prop values match the variant values.
- **A content prop needs no Figma property.** A content prop only sets the text, image, alt text or data a component shows, or passes a value to a nested component. It never changes how the component itself looks or behaves. Anything that does is a design property, and it must exist in Figma, except a runtime prop.
- **A runtime prop needs no Figma property.** A runtime prop is an event handler, or a prop that only says whether the component is open at runtime, such as Dialog Box `open`. It describes a moment in use, not a design choice.
- **Every CSS value is a token.** Use `var(--semantic-token)` for every colour, spacing, radius, size, type and effect value. No hex, no `rgb()`, no `px`, no font family written out.
- **Layout is translated, not eyeballed.** Auto-layout becomes flex or grid with the same direction, alignment, gap and padding, each from its token.
- **Gaps stay visibly unbuilt.** Leave a gap property unset, and record it in a comment naming the gap. Never hide it behind a fallback value.
- **Every state really behaves.** A state is behaviour, not a class that changes colour:

| State | What must actually happen |
|---|---|
| Disabled | The control cannot be activated by click, keyboard or touch. It is removed from the tab order where appropriate, and it carries `disabled` or `aria-disabled` |
| Loading | The control cannot be activated, announces itself (`aria-busy`), and keeps its size so the layout does not jump |
| Focus | A real keyboard Tab shows the focus style through `:focus-visible`, not only a pinned story |
| Hover | A real pointer over the control shows the hover style, and touch does not leave it stuck |
| Selected / checked / current | Reflected in the ARIA state (`aria-selected`, `aria-checked`, `aria-current`) and driven by a prop, not only by styling |
| Error | Exposed to assistive technology (`aria-invalid`, with the message associated), not only coloured |

**Check (must be green):**
- [ ] `npx tsc --noEmit` exits 0.
- [ ] `grep -nE '#[0-9a-fA-F]{3,8}\b|rgba?\(|[0-9]+px|font-family:' src/components/<Name>/<Name>.css` returns nothing.
- [ ] Every `var(--…)` in `<Name>.css` names a semantic token (see the stage 2 check).
- [ ] Every prop name matches its Figma property name exactly, except content props and runtime props, which have none.
- [ ] Every state in the matrix is implemented as behaviour, per the table, and a test click, Tab or hover in the browser proves it.
- [ ] Every gap is unset in the CSS and named in a comment. None has a fallback value.

## Stage 4 · Verify: render every story and compare it with the node

Write `src/components/<Name>/<Name>.stories.tsx`:
- **Put the Figma node URL at the top of the file.** QA tests against the node and starts from this URL.
- Write **one story per matrix row.** Do not merge rows into one story with controls, and do not skip rows.
- A component may also have **example stories**: the export name starts with `Example`, the story name with `Example:`. Each one shows real use taken from a Figma usage note, not a new variant. They are not matrix rows, QA does not test them as cases, and the docs site embeds them on the Examples tab.

Run Storybook locally and look at it. For each story, compare the rendered component with the node's screenshot and metadata: width and height, padding, gap, radius, fill, stroke, type and effects. Read the numbers from the browser's computed style, not by eye. Then drive each state: Tab, hover, click the disabled one, and watch the loading one.

This is your self-check, not QA. QA tests the deployed build independently. Nothing here is a hand-off.

**Check (must be green):**
- [ ] The number of stories, not counting `Example` stories, equals the number of matrix rows.
- [ ] The Figma node URL is at the top of the story file.
- [ ] Every story renders, and the browser console shows no errors or warnings.
- [ ] Every story matches its node on every measured property, or the difference is a listed gap.
- [ ] Every state clicks, tabs or hovers through as the stage 3 table requires, including disabled and loading.

## What you report when done

```
Matrix   <rows> rows from <node URL>: <variant props × sizes × states>
Tokens   <bound>/<total> resolved to semantic tokens
Gaps     <n>: node · variant · property, each left unbuilt for the Designer
Missing  <n> Figma variables with no token in build/css/tokens.css
Checks   1 ✓  2 ✓  3 ✓  4 ✓
```

If any check is red and you cannot make it green, report which stage, which box, and what blocks it, and stop.

## Never

- **Never decide an unbound value.** Report it as a gap.
- **Never substitute the nearest token** for a missing or unbound one.
- **Never invent a token,** and never edit `tokens/` or `build/`.
- **Never use a base token** in a component, even when it is "the same colour".
- **Never fake a state with a class that only changes colour.**
- **Never write a narrower matrix than the component set**, or merge rows to make the story count small.
- **Never start a stage while the previous check is red.**
- **Never build the matrix from an existing story file or another component.** Build it from the node.
- **Never edit another component to make yours work.** Report it.
